## 23/5 指针边界复核（2026-09-22）

再次按鬼作自身反汇编核对后，23/5 仍必须保留显式报错，不能把它标成已实现：

- `4fe130` 先检查索引，再调用 `41cd80`；`41cd80` 通过 `40c5d0` 取 `CBackLog` 槽对象，随后 `41e7a0 -> 4025d0(0)` 返回该槽内部命令向量的 `data()` 指针。
- 该返回值不是 NUL 结尾文本，也没有同时返回字节数。槽向量的终止哨兵属于记录容器约定，不能从裸指针推导出长度。
- `23/8` 的 `4fe060 -> 40b470 -> 406280` 只计算外层槽容器的元素数量；`4fe5f0` 直接丢弃 EAX，不会把它压回 VM，因此不能拿它作为 23/5 payload 长度。
- 当前 `KValue` 只有整数和借用 C 字符串两种可表达值。将该地址伪造成整数会丢失借用关系，将其伪造成字符串会在嵌入 NUL 或缺少哨兵时截断/越界；两者都不符合原版 ABI。

因此当前实现对数值/越界参数保持栈和记录不变，并返回 `23/5 raw backlog command pointer has no safe VM value`。除非先引入带长度、生命周期和只读属性的 VM 字节向量类型并核对所有消费方，否则不应放行 23/5；这不是空操作，而是已核对 ABI 后的安全边界。
